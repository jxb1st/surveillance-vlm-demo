Decision layer

The same frozen ADC items, the same 32 frames, the same Qwen3.8-27B. What changes is how the decision is read out: generated JSON (D0), the model's own probabilities over the option letters (D1), or a separate typed decision model (Laya, Jev-compatible) deciding over the VLM's description (D2). Below that: a real edge trigger, scored per frame on the same videos.

What these runs say

  • Reading the VLM's own probabilities (D1) is worth keeping. Same accuracy as the generated answer (119/120 identical), one fifth of the time, no parsing, and probabilities that work: 97 % accuracy on the 56 % most confident items, abnormal-vs-normal AUC 0.997.
  • A separate zero-shot text decision model (D2) loses the answer. Matching falls to chance (12.5–17.5 %); only "is there an abnormal event" survives in the description (AUC 0.86–0.88). Its blank-state control confirms it does read the description (Rejection 97.5 % → 0 % without it).
  • The fine-tuned text head (D3) scores 95 / 100 / 100 % — and 92.5 / 100 / 100 % with no description at all. Nearly all of its gain over D1 comes from the question and option texts: VALU's Matching options are one-action paraphrases and the Exclusion / Rejection answers are fixed once the option set is recognised, and 2.4k training rows are enough to learn that. The description adds about 2.5 points on Matching and keeps Rejection from drifting (80 % with someone else's description). D3 therefore says more about the benchmark's distractor construction than about video understanding, and it is not evidence for the two-stage recipe.
  • At the edge, nothing trained on ETRI transfers to this footage (frame AUC 0.43–0.58 against 0.64 for frame differencing); the 27B VLM asked the typed questions ranks frames best (0.77) but cannot meet a 1 % false-positive budget. The real-trigger replay turns the three framework cases into one early alarm, one miss and one false alarm.
  • Consequence for the pipeline: keep the typed readout on the server; train the edge trigger on footage like the deployment's (or keep a motion detector); treat a separate decision model as something that needs its own task data and an artifact-free evaluation before it can earn its place.

Protocol notes

  • Decision heads are evaluated on the 120 ADC items of VALU demo subset v1 (adapted protocol), the frozen manifest of the generative runs, with the same cached frames and the same ADC prompt; protocol id valu_demo_v1_decision, separate run ids.
  • D1 reads the next-token distribution after the teacher-forced prefix {"answer_id": ", restricted to the option letters; whether the model's unrestricted next token was a letter is recorded per item.
  • D2's decision model sees the description, the level question and the option texts; never the frames, the reference or the filenames. Laya's budgets were raised from the checkpoint defaults to max_len 1024 / head_max_len 400 so that six to seven long options fit; items whose text was still cut are flagged in the records.
  • No model was trained for D0–D2. D3 is the exception: the text decision model was fine-tuned on VALU ADC items from videos disjoint from the evaluation and smoke sets (manifest valu-demo-v1-decision-train; 10 % of its videos held out for monitoring), so D3 has seen VALU's question style and distractor style, which D0–D2 have not. The edge CNNs were trained on the ETRI CCTV train split (two classes), the same data as the fine-tuned Laya-Vision; VALU footage was never used for training.
  • Edge thresholds are set post hoc at matched false-positive rates on the evaluation videos, so recall numbers compare detectors at equal cost; they are not deployment estimates.
