Qwen3.8-27B

measuredQwen/Qwen3.8-27B
Specification and sources
Checkpoint identity
Qwen/Qwen3.8-27B @ 1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0
Type
Dense causal language model with a vision encoder (model card). Not a mixture-of-experts model.
Visual encoder
ViT, 27 layers, hidden size 1152, patch 16 (pinned config).
Input representation
Frames grouped in temporal patches of 2; 2×2 spatial merge; projected to width 5120 (pinned config).
Token integration
Visual tokens are placed in the token sequence between vision start/end tokens. `deepstack_visual_indexes` is an empty list in the pinned config, so no DeepStack injection is configured for this checkpoint.
Temporal mechanism
Interleaved MRoPE (`mrope_interleaved: true`) plus a text timestamp before each temporal patch, written by the Qwen3VL processor.
Language decoder
64 layers, hidden size 5120. Layout 16 × (3 × Gated DeltaNet → FFN, then 1 × Gated Attention → FFN) (model card; `layer_types` in config).
Output form
Text. Thinking mode is on by default; this demo uses the documented non-thinking mode (`enable_thinking=false`).
Training / adaptation
Pre-training and post-training (model card). Training data at video level: unknown.
Primary sources
Model card · Pinned config.json (checked 2026-09-29)
As run here
bf16, sdpa (PyTorch scaled_dot_product_attention), greedy decoding; thinking: disabled; 32 frames, long edge ≤ 672 px before processor resizing. the processor merges every 2 consecutive frames into one temporal patch and inserts the mean timestamp of the merged frames as text
Training overlap with VALU sources
unknown The model card does not enumerate training videos. Exposure to UCF-Crime or ECVA footage cannot be ruled out.

hypothesis A large decoder with timestamped visual tokens might help with ordering events in longer person-object interactions. This is a hypothesis; see the measured results.

Specification and sources
Checkpoint identity
DAMO-NLP-SG/VideoLLaMA3-7B @ d5b763e368861e7f5096e7ff1b49f92fbccf8ae6
Type
Video-focused multimodal model (model card).
Visual encoder
SigLIP-based any-resolution encoder, 27 layers, hidden size 1152, patch 14 (pinned config; model card names VL3-SigLIP-NaViT).
Input representation
Each frame is encoded at its own resolution; video tokens are merged 2×2 spatially (`video_merge_size: 2`).
Visual-token processing
`use_token_compression: true` in the pinned config: the checkpoint code drops video patches whose pixel difference to the previous frame is below a threshold. Active in our runs; the kept-token count depends on content.
Projection
Two-layer MLP with GELU (`mm_projector_type: mlp2x_gelu`).
Temporal mechanism
The chat template writes `Time <t>s:` before each frame.
Language decoder
Qwen2.5-7B (model card), 28 layers, hidden size 3584 (pinned config).
Output form
Text.
Training / adaptation
See technical report. Video-level overlap with UCF-Crime or ECVA: unknown.
Primary sources
Technical report · Model card · Repository (checked 2026-09-29)
As run here
bf16, flash_attention_2 (flash_attn_varlen_func; per-frame attention in the vision encoder, as in the official implementation), greedy decoding; thinking: not_applicable; 32 frames, long edge ≤ 672 px before processor resizing. checkpoint config enables difference-based visual token pruning for video; the number of visual tokens after pruning is content dependent
Training overlap with VALU sources
unknown Training data are listed at dataset level and do not name UCF-Crime or ECVA; video-level overlap through web video collections cannot be ruled out.

hypothesis Pruning static patches might keep attention on moving subjects in fixed-camera footage, but could also drop slow changes. This is a hypothesis; see the measured results.

Base model
InternVL2-2B, fine-tuned with LoRA (repository README).
Anomaly-focused Temporal Sampler (ATS)
An anomaly scorer plus a density-aware sampler select frames according to anomaly scores (repository README).
Training data
HIVAU-70k hierarchical instruction data.
Full pipeline versus checkpoint-only

ReactVAU

reference · not runno released ReactVAU checkpoint; adapters are trained locall
Specification and sources
Checkpoint identity
no released ReactVAU checkpoint; adapters are trained locally (repository README)
Status in this demo
Architectural reference only. Its trained components are not reproduced here.
Fast detection module
PaliGemma2-3B with Spatial Grid Folding: four frames sampled at 4 FPS are folded into a 2×2 grid and scored through Yes/No logits; one score per second by default (repository README).
Anomaly-Aware Persistent Memory
Fast scores protect suspicious evidence during memory compression (Anomaly Priority Score, Anomaly Pool, dense perception for triggered intervals).
Slow reasoning module
StreamForest-7B backbone, dormant during normal streaming; when triggered it verifies the event from memory and explains it.
Relation to this demo
Closest published design to the edge-trigger → server-VLM framework. Here the trigger is scripted and no memory module exists.
Primary sources
Paper · Repository (checked 2026-09-29)

hypothesis Decoupling monitoring from reasoning matches the edge/server split studied here.
