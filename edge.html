Edge detector

Which detector should run on the camera? Every candidate scores each second of the 88 labelled evaluation videos from the frames alone; an alarm uploads the window around it to the server.

Verdict

  • Best at a 1 % false-alarm budget: MobileNetV3-L 4 frames, VALU-trained — 38% of events, 16 ms per frame, trained on VALU (other videos).
  • Ranking below: event recall at 1 % FPR, then at 5 %, then speed.

Ranking

48 videos with abnormal spans (50 events) + 40 normal videos, 1 fps. Recall at 1 % / 5 % FPR: events detected when at most that fraction of normal seconds is under alarm (threshold chosen per detector on these videos). Alarm window: onset − 10 s to + 20 s.

End to end: trigger → upload → server decision

Each trigger's alarm onsets at its 1 % / 5 % budget become upload windows (−10 s … +20 s, merged); the server VLM answers "is an abnormal event visible?" on each window with the typed readout; an event counts as detected when a window overlapping it is kept at P(yes) ≥ 0.5. 50 events, 1.7 h of labelled video. Cost = GPU-seconds per hour of video (edge at 1 fps + server per window).

Protocol and run ids
  • Protocol valu_demo_v1_edge. Labels: verified TDG spans of abnormal descriptions; Rejection videos as normal. Thresholds are operating points chosen on these videos at matched false-positive rates, not deployment settings.
  • Hardware: Laya-Vision and CNNs on one H200 MIG slice, Qwen on a full H200, motion on CPU; batch 1, JPEG loading included.
  • Training data: "ETRI CCTV" = the ETRI train split (abandoned object, falling; 80 videos); "VALU (other videos)" = VALU videos with verified spans or normal videos outside the evaluation and smoke sets (10 % held out for the epoch choice and temperature). "none" = no training.
  • Replay runs: replay-qwen38_27b-af4768d4e0 (scripted), replay_edge-qwen38_27b-cc96632dc2 (real trigger).
